# Contact form setup

This guide explains how to configure the contact form, email delivery, database
storage, Turnstile protection, and the Cal.com booking embed.

## 1. Create the local environment file

The project already contains a blank `.env.local` file. Add the real values to
that file. Do not commit it or share it.

```env
# Resend
RESEND_API_KEY=
CONTACT_TO_EMAIL=
RESEND_FROM_EMAIL=Compiled Tech <hello@yourdomain.com>

# Supabase
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=

# Cloudflare Turnstile
NEXT_PUBLIC_TURNSTILE_SITE_KEY=
TURNSTILE_SECRET_KEY=
```

After changing `.env.local`, stop and restart the development server:

```bash
npm run dev
```

Environment variables are loaded when Next.js starts. A browser refresh alone
does not reload changed environment values.

## 2. Get the Resend keys

Resend sends the inquiry notification to the Compiled Tech inbox and sends an
automatic reply to the person who submitted the form.

1. Open [resend.com](https://resend.com) and create or sign in to an account.
2. Open **API Keys**.
3. Create an API key with permission to send email.
4. Copy the key immediately and put it in `RESEND_API_KEY`.
5. Set `CONTACT_TO_EMAIL` to the inbox that should receive new inquiries.
6. Open **Domains** in Resend and verify the domain used by the sender address.
7. Set `RESEND_FROM_EMAIL` to an address on that verified domain.

The application reads the sender from `RESEND_FROM_EMAIL`; no source-code
change is needed after the domain is verified. The sender domain must match a
domain verified in Resend.

Example:

```env
RESEND_API_KEY=re_xxxxxxxxxxxxxxxxx
CONTACT_TO_EMAIL=you@yourdomain.com
RESEND_FROM_EMAIL=Compiled Tech <hello@yourdomain.com>
```

For Hostinger, add these values in the protected Node.js application
environment settings rather than committing them to GitHub. Add the DNS
records shown by Resend in Hostinger before testing production email.

## 3. Create the Supabase database

1. Open [supabase.com](https://supabase.com) and create a project.
2. In **Project Settings > API**, copy:
   - **Project URL** to `SUPABASE_URL`
   - **service_role** secret key to `SUPABASE_SERVICE_ROLE_KEY`
3. Never expose the service role key in browser code or a `NEXT_PUBLIC_*`
   variable.
4. Open the Supabase **SQL Editor** and run:

```sql
create table public.leads (
  id bigint generated by default as identity primary key,
  name text not null,
  email text not null,
  company text,
  service text not null,
  budget text not null,
  timeline text not null,
  details text not null,
  created_at timestamptz not null default now()
);

alter table public.leads enable row level security;
```

The server route uses the service role key to insert into `leads`. Do not add
the service role key to client-side code.

Example:

```env
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOiJIUzI1NiIs...
```

## 4. Create the Cloudflare Turnstile widget

Turnstile protects the form from automated submissions.

1. Open [Cloudflare Turnstile](https://dash.cloudflare.com/?to=/:account/turnstile).
2. Choose **Add site**.
3. Give the widget a name such as `Compiled Tech contact form`.
4. Add the production hostname, for example `compiledtech.io`.
5. Add `localhost` while testing locally.
6. Choose the managed widget mode.
7. Copy the **site key** to `NEXT_PUBLIC_TURNSTILE_SITE_KEY`.
8. Copy the **secret key** to `TURNSTILE_SECRET_KEY`.

The site key is safe to expose in the browser. The secret key is server-only.

Example:

```env
NEXT_PUBLIC_TURNSTILE_SITE_KEY=0x4AAAA...
TURNSTILE_SECRET_KEY=0x4AAAA...
```

After restarting Next.js, the Turnstile widget will appear above the submit
button. The form cannot submit successfully until the widget returns a token.

## 5. Create the Cal.com booking link

The booking panel currently points to this placeholder:

```text
https://cal.com/compiled-tech
```

Replace it with your real Cal.com booking URL.

1. Open [cal.com](https://cal.com) and create or sign in to an account.
2. Open **Event Types**.
3. Create an event type such as `Project discovery call`.
4. Choose the duration, availability, timezone, and meeting location.
5. Publish the event.
6. Copy the public booking link. It normally looks like:

```text
https://cal.com/your-username/project-discovery
```

7. Open `src/data/contact.ts`.
8. Replace the `calComUrl` value:

```ts
export const contactInfo = {
  email: "you@yourdomain.com",
  whatsapp: "https://wa.me/15551234567",
  location: "Your City, Country",
  calComUrl: "https://cal.com/your-username/project-discovery",
} as const;
```

The contact page renders the booking iframe inside the `#book` section. The
homepage CTA links to `/contact#book`.

If the iframe is blank after replacing the URL:

- Confirm the URL is the public event URL, not the Cal.com dashboard URL.
- Open the URL directly in a private browser window.
- Confirm the event is published and has available booking hours.
- Restart the Next.js server after changing `contact.ts`.
- Check the browser console for a Cal.com frame-blocking error.

## 6. Replace the contact details

Update the same object in `src/data/contact.ts`:

- `email`: the address shown on the page and used for the mail link.
- `whatsapp`: a full `https://wa.me/` link with the country code and digits.
- `location`: the city and country displayed to visitors.
- `calComUrl`: the public Cal.com event URL.

Use digits only after the country code in the WhatsApp URL. For example,
`+1 (555) 123-4567` becomes `https://wa.me/15551234567`.

## 7. Run the local verification

After all values are configured:

```bash
npm run dev
```

Open:

```text
http://localhost:3000/contact
```

Verify:

1. The form fields are visible.
2. The Turnstile widget loads.
3. The Cal.com booking panel loads.
4. Submit a real test inquiry.
5. Confirm the inquiry arrives at `CONTACT_TO_EMAIL`.
6. Confirm the auto-reply arrives at the submitted email address.
7. Open Supabase and confirm a row was added to `public.leads`.

The API route is:

```text
POST /api/contact
```

If a submission fails, inspect the terminal running `npm run dev` and the
browser Network panel for the `/api/contact` response.

## Security checklist

- Never commit `.env.local`.
- Never paste secrets into client components.
- Never use `SUPABASE_SERVICE_ROLE_KEY` in a `NEXT_PUBLIC_*` variable.
- Never use `TURNSTILE_SECRET_KEY` in a `NEXT_PUBLIC_*` variable.
- Use a verified Resend domain before production.
- Use a production Turnstile hostname before deployment.
